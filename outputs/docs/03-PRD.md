# 03 - PRD（P3 产品需求文档）

- 日期：2026-08-14
- 产品名：**健身助手**
- 依据：docs/01-访谈纪要.md、docs/02-需求文档.md

## 1. 执行摘要

面向「学生/上班族」的移动优先网页应用。用户只需填写一次健身档案，即可获得按「目标 × 训练条件 × 每周天数」自动生成的训练计划，以及按「热量目标 × 忌口 × 厨艺」自动排出的每日食谱（食材单位用个/颗/份，文字分步做法）。配合「训练/三餐/体重」每日打卡和「连续天数/日历/完成率/体重曲线」统计，形成「生成 → 指导 → 打卡 → 反馈」的自律闭环。纯前端、本机存储、零注册，支持 JSON 导出/导入备份。

## 2. 问题陈述（摘要）

见 docs/02-需求文档.md 第二节。一句话：健身新手缺一个"自动安排 + 手把手指导 + 每日打卡 + 坚持反馈"的轻工具，导致难以开始、难以坚持。

## 3. 目标用户

- 主用户：学生 / 普通上班族（20~35 岁），健身小白到半新手，移动端为主
- 单用户模式；不做多人档案

### 4.2 数据模型（开发可直接使用）

```
Profile {
  heightCm: number, weightKg: number, age: number,
  gender: 'male'|'female',
  goal: 'lose_fat'|'gain_muscle'|'maintain',
  weeklyDays: 3|4|5,
  condition: 'gym'|'dumbbell'|'bodyweight',
  avoidances: string[],        // 忌口，如 ['海鲜','香菜']
  cooking: 'beginner'|'easy'|'skilled',   // 厨艺/做饭条件
  calorieTarget: number|null,   // 手动覆盖；null=自动计算
  notifyEnabled: boolean,       // 默认 false
  createdAt: string
}

WorkoutDay {                     // 训练计划 = { dayIndex, title, exercises[] }[]
  dayIndex: 0..6,
  title: string,                 // 如 "胸 + 三头"
  exercises: [{ exerciseId, name, zhName, sets, reps, restSec, tip }]
}

Recipe {
  id, name, category: 'breakfast'|'lunch'|'dinner'|'snack',
  difficulty: 1|2|3, timeMin: number,
  calories: number, servings: number,
  avoidTags: string[],           // 触发忌口过滤
  ingredients: [{ name, qty, unit }],  // unit ∈ {个,颗,份,片,碗,勺,把,根,瓣,杯}
  steps: string[]                // 文字分步
}

DailyPlan {                      // 按日期生成并存档
  date: 'YYYY-MM-DD',
  workout: WorkoutDay | null,    // 当天训练
  meals: { breakfast: MealChoice, lunch, dinner, snack },  // 每餐含 main + alternatives
  checkin: {
    workoutDone: boolean,        // 是否完成训练打卡
    meals: { breakfast: 'eaten'|'skipped'|'replaced', lunch, dinner, snack },
    weightKg: number|null
  }
}

AppData { version, profile, workoutPlan: WorkoutDay[], dailyPlans: Record<date, DailyPlan>, recipeFavorites, ... }
```

**热量公式（内置）**
- 男性 BMR = 10×体重(kg) + 6.25×身高(cm) − 5×年龄 + 5
- 女性 BMR = 10×体重(kg) + 6.25×身高(cm) − 5×年龄 − 161
- TDEE = BMR × 1.375（轻度活动）
- 目标热量 = 减脂 TDEE−400 / 增肌 TDEE+300 / 保持 TDEE；结果四舍五入到 50
- 每餐分配：早餐 30%、午餐 40%、晚餐 25%、加餐 5%

**动作库（数据源）**
- 使用 hasaneyldrm/exercises-dataset（**全量 1,324 个动作**），裁剪字段嵌入：`id, name, category, equipment, target, muscle_group, secondary_muscles, instructions.zh, instruction_steps.zh`
- 中文名词典：覆盖训练模板与高频动作（约 200+ 个），其余动作保留英文名，可同时按「中文/英文名、部位、器械」搜索与筛选
- 动图本地化：仅对训练模板内使用的动作打包 GIF（约 60~80 张）；动作库浏览页按需加载，不一次性加载 1,324 张

## 5. 各功能详细描述与验收标准

### F1 首次引导建档（Must）
**描述**：首次打开显示建档页，分步收集：身高/体重/年龄/性别 → 目标 → 每周可练天数(3/4/5) → 训练条件(健身房/哑铃/徒手) → 忌口(多选标签+自定义) → 厨艺水平(不会做/简单/熟练)。填完进入首页；未完成前不展示首页。
**验收**：
- 每步必填字段有校验（身高 120~230cm、体重 30~200kg、年龄 10~80）
- 档案可保存到本机，重开页面不丢失
- 建档后自动生成训练计划与今日菜单
- 设置中可随时重新编辑档案，编辑后重新生成计划/菜单（保留已打卡记录）

### F2 首页「今日卡片」（Must）
**描述**：首页从上到下：① 顶部：连续坚持天数（🔥 N 天）② 今日训练卡：训练主题 + 动作列表（动作名/组数×次数/休息）+「查看动作」入口 + 完成打卡按钮 ③ 今日菜单卡：早/午/晚/加餐四餐（主菜名 + 热量）+ 替换按钮 + 每餐「吃了/没吃/替换」打卡 ④ 体重录入入口。
**验收**：
- 375px 宽度下无横向滚动，主要按钮 ≥ 44px 点按区域
- 已打卡项显示「已打卡」态，点击可取消（当天内）
- 无今日计划时（如用户删光计划）显示空态引导

### F3 训练计划自动生成（Must）
**描述**：按「目标 × 条件 × 每周天数」从内置模板匹配：每周 N 天分布（如 3 天：胸/背/腿），每天 4~6 个动作，动作从动作库按条件过滤（健身房→器械+自由重量；哑铃→哑铃/徒手；徒手→body weight），组数/次数按目标调整（增肌 8~12 次×3~4 组、减脂 12~15 次×3 组+穿插有氧、保持 10~12 次×3 组）。
**验收**：
- 每种「目标 × 条件 × 天数」组合（3×3×3=27 种）都有可用模板，不会生成空计划
- 每个动作必带动作库 id、组数、次数、休息秒数、一句话要点
- 减脂目标含每周 ≥2 次有氧/循环类动作
- 生成结果可整体重新生成（换一套模板）

### F4 训练计划查看与手动编辑（Must）
**描述**：可进入「本周训练」页查看 7 天安排；每天可：添加动作（从动作库搜索选择）、删除动作、调整顺序、修改组数/次数/休息；可修改天数分布（如从 3 天改 4 天）。
**验收**：
- 增删改实时保存到本机
- 搜索动作支持按名称/部位/器械筛选（英文名+中文词典可搜）
- 修改后当日打卡记录不受影响

### F5 动作详情（Must）
**描述**：点击动作进入详情页：动作名（中英）、目标肌群/次要肌群/器械、动画 GIF（如已打包）、中文分步教程（instruction_steps.zh 分步展示）、完整说明。
**验收**：
- 分步教程逐条渲染（有序列表）
- 无 GIF 时显示占位图不报错
- 页面在手机上可流畅滚动

### F6 每日菜单自动生成（Must）
**描述**：按目标热量自动排「早餐/午餐/晚餐/加餐」；每餐从菜谱库按类别+忌口过滤+厨艺难度≤用户水平 挑选主菜，并给出 3 个候选替换菜。菜单按「今日」生成并固定当日，跨天自动生成新菜单。
**验收**：
- 生成的菜单不含忌口标签命中项
- 主菜难度 ≤ 用户厨艺（beginner 只出难度 1，easy 出 1~2，skilled 出 1~3）
- 四餐热量总和 ≈ 目标热量（±15%），展示每餐热量
- 菜单每日存档，历史可回看（F13）

### F7 菜单一键替换（Must）
**描述**：每餐展示主菜 + 3 个候选，点候选即替换主菜；替换后当天有效，不改变次日菜单。
**验收**：
- 替换后主菜与候选互换，已替换标记可见
- 若某餐候选被忌口/难度过滤后不足 3 个，从同类宽松补足并标记

### F8 菜谱详情（Must）
**描述**：菜谱详情页：菜名、难度/用时/热量、食材清单（数量+单位，单位用 个/颗/份/片/碗/勺/把/根/瓣/杯，不用克/毫升）、分步做法（文字步骤）、适合餐次。
**验收**：
- 食材数量为自然单位，不含「克/毫升」
- 步骤为有序分步列表
- 可收藏/取消收藏（F16 用）

### F9 每日打卡（Must）
**描述**：打卡三项：① 训练完成（✅/未完成，当天可改不可补）② 三餐（每餐三态：吃了/没吃/替换成别的）③ 体重（可选数字输入）。
**验收**：
- 打卡写入当天 DailyPlan，刷新不丢失
- 超过当天 23:59 后当天记录锁定不可修改（不可补卡）
- 体重输入校验 30~200kg，保存后更新体重曲线
- 打卡完成态在首页有正向反馈（如全部完成显示鼓励语）

### F10 统计（Must）
**描述**：「我的数据」页：① 连续坚持天数（按训练打卡连续计算）② 月度日历（当天训练完成/未完成/休息着色）③ 周完成率（本周训练完成次数/计划次数）④ 体重曲线（折线图，按时间）。
**验收**：
- 连续天数跨月连续计算（7月31日→8月1日 不断）
- 日历按月翻页，可点击某天进入当天详情（F13）
- 体重曲线按录入顺序/日期排序，数据点 ≥2 才显示曲线，否则提示
- 无数据时有空态引导

### F11 本机存储 + 导出/导入（Must）
**描述**：所有数据存 localStorage（数据量小，档案+计划+打卡+菜谱收藏；动作库与菜谱库作为静态资源随应用打包）。设置页提供「导出数据」（下载 JSON 文件，含 AppData 全量）与「导入数据」（选择 JSON 文件，覆盖式恢复）。
**验收**：
- 导出文件为合法 JSON，含版本号，可被导入恢复
- 导入前二次确认（将覆盖现有数据）
- 导入后页面数据刷新且不报错
- 动作库/菜谱库不随导出文件包含（静态资源）

### F12 设置（Must）
**描述**：设置页：① 编辑健身档案 ② 热量目标显示与手动覆盖（可改回自动）③ 通知开关（默认关）④ 数据导出/导入 ⑤ 关于（数据来源署名、版本）。
**验收**：
- 热量覆盖保存后，次日菜单按新热量生成（当日菜单不重排）
- 通知开关状态持久化
- 关于页包含动作库署名「Exercises dataset © Gym visual / hasaneyldrm」

### F13 历史回看（Should）
**描述**：日历点击任意日期，查看当天：训练计划（当时内容）、三餐菜单（含是否替换）、打卡状态、体重。
**验收**：
- 未来日期可预览（基于当前生成逻辑的当日内容），标注「未打卡」
- 历史日期显示存档内容，数据与当时一致

### F14 浏览器通知（Should）
**描述**：开启后，在网页打开状态下，于设定提醒时间（默认 20:00）发送「今日训练/饮食还没打卡」通知（Notification API）。
**验收**：
- 需用户授权（浏览器权限），拒绝后开关自动关闭并提示
- 权限不可用时提示"当前浏览器不支持"

### F15 从动作库添加任意动作（Should）
**描述**：编辑训练日时，可从完整动作库搜索（名称/部位/器械）并添加任意动作到计划。
**验收**：
- 搜索结果按名称（中英）、部位、器械过滤
- 添加后可设组数/次数/休息

### F16 周菜单预览（Could）
**描述**：「本周饮食」页展示未来 7 天菜单预览（按当前档案预生成）。
**验收**：
- 每天四餐完整展示；点某天可固定/替换（替换后当天存档生效）

### F17 深色模式（Could）
**描述**：跟随系统偏好提供深色配色。
**验收**：系统深色时自动切换，主要界面对比度达标（见设计规范）。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 首屏可交互 ≤ 3s（4G）；动作库按需懒加载；页面无卡顿滚动 |
| 兼容 | 现代浏览器：Chrome/Safari/Edge；移动端 iOS Safari ≥ 15、Android Chrome ≥ 90 |
| 安全 | 纯本地存储，无网络上传；不引入第三方 Cookie/统计 |
| 可维护 | 数据模型带版本号（v1），升级可迁移；代码模块化（数据/生成器/UI 分离） |
| 无障碍 | 主要操作可键盘触达；文本对比度 ≥ 4.5:1；表单有 label |
| 版权 | 动作库数据 MIT；图片/GIF © Gym visual 需在「关于」署名 |

## 7. 里程碑

- **M1 核心闭环**：F1/F2/F9/F10/F11/F12（建档→首页→打卡→统计→备份）
- **M2 训练模块**：F3/F4/F5/F15（计划生成/编辑/动作详情）
- **M3 饮食模块**：F6/F7/F8/F16（菜单生成/替换/菜谱）
- **M4 打磨交付**：F13/F14/F17 + 全流程回归

## 8. 边界与风险

| 风险 | 缓解 |
|---|---|
| 动作名英文、无中文名 | 中文词典覆盖 200+ 常用动作；其余保留英文名，支持按部位/器械/中英文搜索 |
| 动作库数据量 | 全量 1,324 条裁剪字段后约 2~4MB，作为静态资源打包；GIF 按需懒加载 |
| 菜谱热量为估算 | 标注"估算值"；热量可按目标上下浮动 15% |
| localStorage 容量（~5MB） | 数据量小（纯文本），预留容量检查与导出提示 |
| 浏览器通知不可靠 | 定位为辅助，主入口始终是首页待办 |
| 本地数据丢失 | 提供导出/导入；首次建档后提示"建议导出备份" |
