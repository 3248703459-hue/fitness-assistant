## 一、用户画像

### 主画像：忙碌的健身小白/半新手

| 维度 | 描述 |
|---|---|
| 身份 | 学生或普通上班族，20~35 岁 |
| 健身经验 | 小白到半新手：知道要练、但不知道练什么、怎么吃 |
| 时间 | 每周能挤 3~5 次锻炼时间，做饭时间有限（工作日更少） |
| 工具习惯 | 手机为主，能接受"打开网页就用"，不愿安装复杂 App |
| 情绪状态 | 想自律但常半途而废；要么瞎练没效果，要么直接放弃 |
| 场景 | 宿舍/出租屋/办公室附近健身房；徒手、哑铃、健身房器械都有可能 |

### 次要画像（暂不支持，仅记录）

- 进阶健身者（需要记录重量/组数/动作级数据）→ 后期版本
- 家庭共用（多人档案）→ 后期版本

## 二、问题陈述（problem-statement）

**I am（我是谁）：** 一个想通过健身变得更好、但缺少科学安排和坚持动力的学生/上班族。

**Trying to（我想做到）：** 不用自己研究，就能知道「今天练什么、怎么练、动作怎么做」，同时知道「今天吃什么、怎么做」，并且能坚持记录、看到自己的进步。

**But（但阻碍我的是）：** 网上信息太多太散，我分不清适合我的计划；收藏了一堆视频但从没行动；没人告诉我今天具体该做什么；坚持几天看不到正反馈就放弃。

**Because（根本原因）：** 我没有"教练"和"营养师"，也没有一个把「计划 → 指导 → 打卡 → 反馈」串起来的简单工具；App 市场里要么太复杂（要手动建计划、填数据），要么是内容平台（看完就忘）。

**Which makes me feel（这让我感到）：** 迷茫、拖延、挫败，甚至自责「又没坚持」。

**Context & Constraints（背景与约束）：**
- 移动端优先、网页即开即用、数据存本机（隐私、无注册）
- 用户时间碎片化，计划要"生成即用、少填写"
- 第一版单用户、只做健身

**Final Problem Statement（最终问题陈述）：**
> 一个想自律的健身新手，缺少「根据自身情况自动生成 + 手把手指导 + 每日打卡 + 坚持反馈」的一站式轻工具，导致难以开始、难以坚持、看不到进步。

## 三、Jobs-to-be-Done（用户要完成的任务）

### 功能型任务（Functional Jobs）
1. 一次性提供我的身体/目标/条件信息，让工具了解我
2. 拿到一份「今天练什么、每个动作怎么做」的训练计划
3. 拿到一份「今天吃什么、怎么做」的每日食谱（含替换选择）
4. 快速完成每日打卡（训练、三餐、体重），记录坚持情况
5. 回看历史与统计，确认自己真的有进步

### 情感/社交型任务（Emotional Jobs）
1. 获得"被安排好了"的省心感，不用每天纠结
2. 连续坚持带来的成就感（连续天数、完成率）
3. 避免"瞎练/乱吃"的焦虑，感到自己走在科学路径上

### 痛点（按强度排序）
| 强度 | 痛点 |
|---|---|
| 🔴 高 | 不知道今天具体该练什么/吃什么 → 直接不行动 |
| 🔴 高 | 动作不会做、怕受伤 → 不敢练 |
| 🟠 中 | 计划/食谱不适合自己的条件（没器械、不会做饭、忌口） |
| 🟠 中 | 看不到进步 → 3 天热度后放弃 |
| 🟡 低 | 记录麻烦（手动输入太多）→ 懒得记 |

### 收益（Gains）
- **省心**：打开就知道今天干什么，决策成本≈0
- **科学**：训练按目标/条件匹配，食谱按热量/忌口/厨艺筛选
- **可感进步**：连续天数、月度日历、完成率、体重曲线
- **安全**：动作有中文分步教程，降低受伤风险
- **数据自主**：本机存储 + 一键导出备份

## 四、机会解决方案树（OST）

```
目标：让用户"开始得动、坚持得住、看得到进步"
        ├── 机会1：决策负担太重，不知今天练什么/吃什么
        │     ├── 方案A：自动生成今日训练+今日菜单（首页今日卡片）✅ 选中
        │     ├── 方案B：提供海量内容库让用户自己选（❌ 反向，加重负担）
        │     └── 方案C：AI 聊天式问答（❌ 复杂且本机无法做）
        ├── 机会2：动作不会做/怕受伤
        │     ├── 方案A：动作库中文分步教程+GIF ✅ 选中
        │     ├── 方案B：外链视频（❌ 依赖网络与第三方）
        │     └── 方案C：纯文字描述（❌ 信息不足）
        └── 机会3：坚持无反馈，容易放弃
              ├── 方案A：连续天数+完成率+日历+体重曲线 ✅ 选中
              ├── 方案B：社交打卡（❌ 超范围，且需账号）
              └── 方案C：强提醒推送（❌ 网页能力受限）
```

**Selected POC（第一版交付范围）：**
- 机会 1 → 方案 A（今日卡片：训练+菜单+打卡一体）
- 机会 2 → 方案 A（内置动作库中文教程）
- 机会 3 → 方案 A（坚持数据可视化）

**假设（Hypothesis）：**
> 如果用户打开即看到"今天练什么、吃什么"，且动作有中文分步教程、坚持有可视化反馈，那么用户会更容易开始行动并持续打卡。

## 五、成功指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 首次建档完成率 | 打开后完成档案填写的人数占比 | 高（引导只问必要项） |
| 周完成率 | 每周完成训练打卡天数 / 计划训练天数 | ≥ 70% |
| 连续坚持天数 | 连续完成训练打卡的天数 | 用户可感知增长 |
| 饮食打卡参与率 | 至少打卡一餐的天数占比 | ≥ 50% |
| 手动覆盖使用率 | 用户修改生成计划/菜单的次数 | 有使用即说明"可自定义"生效 |

## 六、范围边界（确认不做）

- ❌ 学习、生活模块（已明确暂停）
- ❌ 账号/云端同步/多设备
- ❌ 多人档案、社交、分享
- ❌ 动作级重量组数记录（后期）
- ❌ 视频教学、AI 问答
- ❌ 微信/短信等强推送
